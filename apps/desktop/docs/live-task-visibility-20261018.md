# 主对话委派、独立子对话与 Live 工作回执

目标 Profile：`huawei_ict_agentarts`。Desktop 启用可信组合选项 `delegateUserTasks:true`：主对话只派发和汇总，实际工作经原 Runtime/Policy/ToolGateway 在持久化子任务中执行。

### 主对话与实际执行边界（2026-10-20，#430）

主对话负责用户交互、委派和汇总，实际工作继续由原持久化 `user-work` 子智能体执行。所有新用户工作都冻结原 `required-subagent-delegation` 绑定，短句、只读天气等查询也不例外；根任务只经 `subagent.dispatch` 派发，不直接调用业务工具。

原拟加入的根任务直答路由已按用户确认撤回。单个成功子任务的结果可直接透传到主对话，避免重复协作汇总头，但这只是展示/汇总行为，不改变执行归属。Runtime、Policy、ToolGateway、审批、Evidence 与无 Local 静默回退的边界保持原有链路。

## 问题与行为

旧版工作区按当前工作区对话过滤父任务，导致语音面板所属对话的子任务被排除。实际旧版窗口读回：面板有 5 条子任务，工作区为 0 条。

大工作区移除任务内容输入框、发送与停止操作，只保留概览和最近六个子智能体入口，三列、最多两行。列表从原 TaskRuntime 持久记录读取；追加消息仍归原子智能体，最近有新执行的入口前移。小“更多”按钮打开全部历史页面，支持分页、刷新、搜索已加载记录并准确打开对应子对话；不会删除、归档或截断旧记录。

每个子智能体在独立窗口拥有输入框、发送和停止。原目标、回答、模型、强度、状态与步骤可展开查看；后续用户消息与已保存回答按轮展示。发送会创建同一子对话的新执行任务，不重开原任务终态，也不增加另一层子智能体。提交成功只代表受理；停止回执也不代表已经停止。相同子智能体复用原窗口，刷新不会清空未发送草稿，关闭窗口不取消任务。

小面板不常驻子任务列表。首次快照静默建立基线，后续首次成功才显示“某某子智能体已完成 ✓”，可点击查看或关闭，约八秒自动消失；重启不重播历史成功。直接出现的成功记录须有挂载后可信 Runtime 更新时间，否则保持静默。

新用户任务受理时冻结原 `user-work` 子任务绑定，包括目标、期限、模型、原生推理强度及步骤预算。第一步确定性生成原 `subagent.dispatch` 提案，仍经现有 Policy 和 Gateway；不是先在根执行后修改显示名称。根工具范围仅允许原派发，云端只能在已确认的子任务回执之后汇总，不能借汇总继续执行业务。子任务保留现有工具范围和禁止递归派发边界。`readDelegatedUserTaskParent()` 校验原绑定、幂等关系、取消及期限后，仅供公开受限历史读取；不转移私人记忆或 Skill 许可。

本机 IPC `task.openSubagentConversation` 和 `task.subagentConversation` 在读取前核对原父任务、Runtime 父子绑定和子任务 conversationId，不再限于 Desktop 已加载缓存。独立窗口身份固定在可信主进程，只接受无参数 `subagentConversation.snapshot`、`.close`、`.main`，以及限定字段的 `.submit({text,requestId})`、`.cancel({taskId})`；不接受替换原父子身份、任意 `task.submit`、审批或模型管理。取消须匹配此子对话的实际活动执行。全部历史窗口仅允许分页、打开已校验原子对话和关闭。窗口尺寸不写入常规工作区的持久布局；大工作区通用 `task.submit` 也在主进程拒绝。

原任务详情仅使用公开 `readSubagentTasks` / `runtime.getTask`，不读取私有循环检查点。Runtime 新增可信宿主端口 `readSubagentConversation`、`submitSubagentConversationMessage`、`cancelSubagentConversationTask`、`listSubagentConversations` 和 `readSubagentConversationOrigin`，复用原 TaskRuntime/SQLite、取消、恢复、Policy 和 ToolGateway。持久消息绑定原子智能体、请求标识、模型、预算、工具范围及配置；同请求重试保持幂等，换参数拒绝，同子对话一次只运行一个执行。执行前重新核对配置和工具目录，权限重新审批，未知写入保持待核实，不能借追加消息重做。

原始完整内部模型逐轮记录仍不作为公开会话提供，返回 `transcriptAvailable:false`；可读的是原任务持久目标/回答，以及新增消息的用户输入、已保存回答和实际状态。原 `task.openConversation` 仅保留本机父任务定位兼容，独立子窗口不获得该动作；子窗口返回当前主对话，不切换其他面板会话。旧子任务缺少完整执行绑定时保留只读详情并明确不可发送，不自动迁移或猜测权限。

Live 增加提交中、已受理、回执已返回和结果待核实反馈。语音被打断或播放结束时，仍有工作等待则保持工作状态。上下文提供实际 `subagent.dispatch` 注册/可用性和当前对话的子任务摘要，避免语音模型凭空宣称接口关闭。提示词要求明确派发请求经过 `request_work`，但提示词不构成接口必调用或任务成功的证明。

结果中的 Evidence 仅展示数量，不展示原始引用。执行记录、模型自报与独立验证分别解释；成功记录仍可标记 `verification=unverified`。

## 限制与恢复

没有新开启麦克风、重放计算、调用付费模型或执行云端工具闭环。Runtime 集成用显式 Fake Coordination/工具；实际窗口只读取已有记录。不能据此认定语音模型每次都会调用 `request_work`，或原结果已独立验证。

`delegateUserTasks` 只绑定新用户任务，旧任务不追补。每次绑定一个原始 `user-work` 子任务；不是动态多执行器规划。重启仍遵循已保存绑定，即使随后关闭该组合选项也不改写原任务。私人记忆及 Skill 的单任务许可不迁移：现 Desktop 明确拒绝不覆盖子任务的选择，不能把旧确认改成子任务授权。追加会话只提供本子对话允许的历史，原任务涉及私人/Skill 上下文时不自动作为新消息种子；Desktop 在提交和实际发送前还检查原 Skill 范围。

子任务未知写入保持原 `waiting_reconciliation`，禁止重派；父任务可能仍保留既有 `waiting_approval`，不宣称成功。子任务完成而根云端汇总失败时保留原子结果，现恢复 API 不保证可以单独重试汇总；不能通过再次派发来补造成功。这两项恢复能力不在本次扩展。

启动前保留现有配置备份。可正常退出后切换版本；有新委派任务时应保留支持该 checkpoint 的 Runtime，禁止用旧版重新提交原任务来“回退”。未合并修复分支与 main 分别记录，不把运行分支称为已合并 main。
