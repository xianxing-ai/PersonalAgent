# 主对话委派、独立子对话与 Live 工作回执

目标 Profile：`huawei_ict_agentarts`。Desktop 启用可信组合选项 `delegateUserTasks:true`：主对话只派发和汇总，实际工作经原 Runtime/Policy/ToolGateway 在持久化子任务中执行。

## 问题与行为

旧版工作区按当前工作区对话过滤父任务，导致语音面板所属对话的子任务被排除。实际旧版窗口读回：面板有 5 条子任务，工作区为 0 条。

大工作区从主进程已加载父任务中取最近六条子任务，按 Runtime 更新时间排序，三列、最多两行。点击标识打开各自独立窗口，显示 Runtime 已保存目标、回答、模型、强度、状态与步骤，可刷新、关闭或返回当前主对话；相同任务复用原窗口。

小面板不常驻子任务列表。首次快照静默建立基线，后续首次成功才显示“某某子智能体已完成 ✓”，可点击查看或关闭，约八秒自动消失；重启不重播历史成功。直接出现的成功记录须有挂载后可信 Runtime 更新时间，否则保持静默。

新用户任务受理时冻结原 `user-work` 子任务绑定，包括目标、期限、模型、原生推理强度及步骤预算。第一步确定性生成原 `subagent.dispatch` 提案，仍经现有 Policy 和 Gateway；不是先在根执行后修改显示名称。根工具范围仅允许原派发，云端只能在已确认的子任务回执之后汇总，不能借汇总继续执行业务。子任务保留现有工具范围和禁止递归派发边界。`readDelegatedUserTaskParent()` 校验原绑定、幂等关系、取消及期限后，仅供公开受限历史读取；不转移私人记忆或 Skill 许可。

本机 IPC `task.openSubagentConversation` 和 `task.subagentConversation` 在读取前核对已加载原父任务、Runtime 父子绑定和子任务 conversationId。独立窗口身份固定在可信主进程，只接受无参数 `subagentConversation.snapshot`、`.close`、`.main`；拒绝任务提交、审批、取消及身份替换，关闭窗口不取消任务。窗口尺寸不写入常规工作区的持久布局。

详情仅使用公开 `readSubagentTasks` / `runtime.getTask`，不读取私有循环检查点。Runtime 没有公开的完整逐轮会话读取端口，返回 `transcriptAvailable:false`；部分循环检查点可能保存消息，这不构成完整会话可读。

历史加载范围以主进程现有任务缓存为限，并非全库搜索。原 `task.openConversation` 仅保留本机父任务定位兼容，独立子窗口不获得该动作；新子窗口返回当前主对话，不切换其他面板会话。

Live 增加提交中、已受理、回执已返回和结果待核实反馈。语音被打断或播放结束时，仍有工作等待则保持工作状态。上下文提供实际 `subagent.dispatch` 注册/可用性和当前对话的子任务摘要，避免语音模型凭空宣称接口关闭。提示词要求明确派发请求经过 `request_work`，但提示词不构成接口必调用或任务成功的证明。

结果中的 Evidence 仅展示数量，不展示原始引用。执行记录、模型自报与独立验证分别解释；成功记录仍可标记 `verification=unverified`。

## 验证

- 105 项定向测试通过：Desktop 70 项（Live host/controls 35、只读活动/详情 8、独立页 9、完成提示 6、子窗权限 2、工作区设置隔离 10）；Runtime 35 项（新增委派 17、既有默认子任务和父任务恢复 18）。涵盖真实持久化子任务、根业务工具拒绝、模型/预算绑定、审批与重启不重派、伪造上下文拒绝、公开历史、汇总失败保留原结果。Runtime 与新增主进程接线使用 pinned Node 24.15.0；部分纯 JS 组件测试使用 bundled Node 24.19.0。
- 真实 Electron 使用现有用户配置启动，读取六条已有持久化子任务。实际验证两行列表、小面板无常驻列表且不重播历史成功、两个独立子窗口分别绑定原任务、目标/回答与 Runtime 一致、身份替换拒绝、刷新/返回主对话/关闭以及页面无异常。完成提示的新增成功路径使用显式 Fake DOM/时钟测试，未创建新真实任务来制造提示。
- 检查实际截图、脚本语法与 `git diff --check`。本机截图/检查报告位于被忽略的缓存目录，不进入 Git。
- Runtime TypeScript 编译及受影响 JS 语法检查通过；无 wire Schema、依赖或数据库迁移。新增可信组合选项及 checkpoint，不放宽任何原有授权；无 Local 回退。

## 限制与恢复

没有新开启麦克风、重放计算、调用付费模型或执行云端工具闭环。Runtime 集成用显式 Fake Coordination/工具；实际窗口只读取已有记录。不能据此认定语音模型每次都会调用 `request_work`，或原结果已独立验证。

`delegateUserTasks` 只绑定新用户任务，旧任务不追补。每次绑定一个原始 `user-work` 子任务；不是动态多执行器规划。重启仍遵循已保存绑定，即使随后关闭该组合选项也不改写原任务。私人记忆及 Skill 的单任务许可不迁移：现 Desktop 明确拒绝不覆盖子任务的选择，不能把旧确认改成子任务授权。

子任务未知写入保持原 `waiting_reconciliation`，禁止重派；父任务可能仍保留既有 `waiting_approval`，不宣称成功。子任务完成而根云端汇总失败时保留原子结果，现恢复 API 不保证可以单独重试汇总；不能通过再次派发来补造成功。这两项恢复能力不在本次扩展。

启动前保留现有配置备份。可正常退出后切换版本；有新委派任务时应保留支持该 checkpoint 的 Runtime，禁止用旧版重新提交原任务来“回退”。未合并修复分支与 main 分别记录，不把运行分支称为已合并 main。
