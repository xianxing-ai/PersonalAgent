# Solid Glass 与普通设置增量（2026-10-27）

目标为 `huawei_ict_agentarts` Competition Profile 的 Desktop，基线为主线 `4dbf01e1ffbb1179f8a600abf63db0fcd917afa5`。设计参考 [Solid Glass](https://github.com/deeplethe/solid-glass) 的中性色、表面厚度、细高光和清晰文字；本项目以现有原生 HTML/CSS 实现，没有引入其 React、Tailwind 或组件依赖。

## 交付范围

- 常规、连接与提醒、隐私与权限成为普通设置入口；原页面仍由高级设置、搜索和已有宿主导航进入。连接诊断和本地判断组件折叠，日历 UID 与订阅原任务编号保留在高级操作中。
- 工作区、设置、悬浮面板、独立桌面偏好、MCP 管理和配对窗口采用同一层次的深浅材质。悬浮面板保留原 Windows 原生背景，增加不透明度以改善真实桌面上的文字对比；设置页不在每张卡片上叠加实时背景模糊。独立桌面偏好的主题仍是独立配置域。
- 移除会被 Main 拒绝的目标管理旧预授权按钮；设置只打开原对话和撤销旧许可，目标操作仍走原提问卡、Policy 与 ToolGateway。新增私有 `conversation.open` 仅允许已登记的 Admin 主框架发起，不接受参数。
- 待办和订阅只在有效回执后清除未被用户改写的普通输入；重复提交受限，结果未知或收到取消但尚未读回时保留草稿、要求先核对列表，且不自动重发。旧回复不覆盖较新的宿主快照；未变化的列表不重复创建 DOM。
- 首次无工作区配置时，在 Electron `userData` 下准备 `Workspace`，以独占探针确认读写并清理探针，将路径经原 `safeStorage` 加密，以不覆盖现有文件的方式发布配置。已有文件（包括不可解密或损坏的文件）保持原字节；失败明确报告。重启后由主进程读回目录名称，显示“已保存、待装配”，不会把路径或密文发送到 Renderer。目录配置不授予读取、写入、执行或出机权限，工具装配仍依赖原宿主及对话授权。Runtime 尚未装配时选择按钮不可用。

## 2026-10-28 圆角与简化配置

- 工作区默认按已保存的普通窗口尺寸打开，不再每次强制最大化；设置窗口开启系统圆角和阴影。Windows 11 原生窗口合成裁切四角，最大化仍按系统行为铺满；Windows 10 上 Electron 的原生无边框圆角不生效。系统圆角不改变原窗口拖动、缩放或授权链。
- 新的 AgentArts 连接表单默认 HTTPS / Latest，固定版本和 WSS 参数移入高级连接设置。已有本机 WSS、固定版本及凭据继续按原配置读取；实时音频所需的 WSS 仍需真实配置和验收，Latest 不等于已读回部署版本。
- 首次启用开发任务规划时，Main 使用 32 步默认上限；自动摘要保留默认的 96,000/64,000 字符触发与目标等预算。预算、模型原生参数和开发工具配置折叠在可选区域；显式保存过的自定义值继续保留，摘要模型必须手动选择可用版本。摘要、事件接入及原生模型参数均不自动启用，出机确认和原授权照常执行。加密模型配置读取失败时，保存 Harness 不再覆盖原文件。
- Windows 11 实机使用隔离的空 Competition 配置检查工作区、设置窗口四角与深浅主题；普通窗口、最大化、还原和缩放路径通过真实 Electron 冒烟。普通设置测试经 Main/Preload 保存并读回 32 步默认值，验证摘要及事件仍关闭。相关配置宿主和表单测试使用合成凭据/依赖，验证历史值、版本冲突、无效输入和损坏文件保护，没有请求真实模型。
- 2026-10-28 曾因本机 Git 和 GitHub API 直连失败而无法复核主线；随后通过现有系统代理只读获取上游 `main`，确认基线仍为 `4dbf01e1ffbb1179f8a600abf63db0fcd917afa5`。

## 卡顿采样

同一 Windows 主机、Electron 实际工作区、DPR 1.5、隔离空白配置及无真实模型请求，使用同一探针依次改变约 1500×258 px 的星云画布宽度，每次间隔 220 ms。计时覆盖 Renderer 中 `paint` 回调；排除尺寸未变时不足 1 ms 的空回调。原实现 8 次有效绘制中位数 32.35 ms、最大 43.70 ms；调整云层分辨率后 6 次有效绘制中位数 12.25 ms、最大 14.20 ms。窗口连续改变尺寸时使用 100 ms 合并重绘，已有画布由 CSS 暂时缩放；星点仍按显示分辨率绘制，装饰性星云呼吸动画停止。

这是单机、小样本的特定绘制路径对照，不证明所有机器或整个应用没有卡顿。已合并的 #505 和 #523 性能修复继续保留；本轮没有读取用户历史数据库或对真实用户资料做 profiler。
