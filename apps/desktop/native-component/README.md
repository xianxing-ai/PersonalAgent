# Windows native desktop distribution component

Run `node apps/desktop/scripts/publish-native-desktop.mjs` on Windows with .NET 8 SDK. The equivalent explicit build entry is `node apps/desktop/scripts/build-windows-host.mjs --publish-native-desktop`. Neither command uses Python. Normal prestart continues to use the fixed incremental development build; packaged preparation only reads its bundle.

The publisher pins Microsoft.NETCore.App and Microsoft.WindowsDesktop.App **8.0.30**, RID **win-x64**, protocol **personal-agent-desktop/1**, component version **1.0.0**. It disables shared compiler/build servers and applies the original deadline/cancellation to its own subprocess tree. Failure leaves an incomplete cache directory for diagnosis and does not promote or overwrite an earlier bundle. Never package an output unless the command succeeds and both manifest and identity receipt exist.

Output is a fresh ignored `.cache/native-desktop-publish/<id>/resources/native-tools/desktop/`. Copy the complete contents to the application's existing `resources/native-tools/desktop/` location; do not copy only the executable. The top-level adjacent `identity-receipt.json` records an initialize-only smoke test with external .NET lookup disabled. No window enumeration, screenshot or user input is requested. This smoke test on the development machine is not clean-OS installation/uninstallation acceptance. No installer, signature or license for project source is introduced here.

The same explicit `build:windows-host -- --publish-native-desktop` command also stages the independent self-contained Job helper under `resources/native-tools/workspace-command/`. It first publishes through the public coding-tools helper into a new external directory, then copies and verifies every file in the formal resources tree. Copy this complete sibling component too; its `job-component-manifest.json` and `job-identity-receipt.json` are separate from the Desktop component. `readPackagedNativeJobHelper(resourcesPath)` reads the actual packaged path and refuses missing, changed or FDD-only bundles. Existing nonempty components are never overwritten. Development `prestart` behavior is unchanged; no installer or packaged Main availability is implied until that consumer is wired.

The command also publishes `resources/native-tools/windows-host/{host,bridge}` as a separate Host/PipeBridge component, fixed to .NET / Windows Desktop 8.0.30 and win-x64. Its complete `windows-host-component-manifest.json` includes both runtimes, the original protocol schema and upstream licenses. `windows-host-identity-receipt.json` records only the original ordinary-user peer verification and hello/EOF exchange with external .NET disabled. `readWindowsHostComponent(resourcesPath)` captures both exact executable paths and the manifest SHA; pass its `assertCurrentBundle` with those paths to the existing Runtime transport. That check runs before each connection and frame. No Notepad observation or write is part of publication. The old FDD development paths remain available only with a suitable globally installed runtime; inherited `DOTNET_ROOT`, startup hooks and arbitrary environment values are no longer a transport dependency.

`component-manifest.json` contains the fixed runtime identity, actual SDK, Git HEAD, scoped dirty status, sorted source hashes/source digest, and SHA-256/size for every bundled file. The manifest and its SHA sidecar are explicitly excluded from their own inventory; `component-manifest.sha256` covers the exact manifest bytes. Build output paths are local artifacts, not part of the public manifest. Source hashes distinguish uncommitted implementation from the recorded HEAD. A hash is integrity evidence, not a digital signature or proof of publisher trust.

`upstream/sources.json` pins verbatim license/notice files to the source revisions of .NET 8.0.30 runtime packs. WindowsDesktop's pinned `eng/Version.Details.xml` identifies its WPF and Windows Forms revisions. The publisher verifies the recorded bytes before copying them into `licenses/` and refuses a different runtime version. The generated attribution index grants no additional rights. Review and refresh the pinned runtime, sources, hashes and notices together when upgrading .NET; the publisher performs no automatic version upgrades or network downloads of license material.

The scoped upstream `.gitattributes` disables line-ending conversion for the pinned legal payloads and preserves their original notice trailing spaces. This keeps checkout bytes equal to `sources.json`; it does not relax whitespace checks for first-party code or change the upstream notices.
