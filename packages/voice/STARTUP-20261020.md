## 新增的进程内公开入口

`createVoiceStartupController({output?, listening?})` 消费已有 `SpeechOutputPort` 和
`ContinuousVoiceListeningPort`。后者由 `createVoiceHostListeningPort(liveVoice)` 适配原
Live host 的 `start/stop/hasActive`。不创建第二个录音循环、模型入口、任务库或调度器。

- `start({enabled,greet,listen,signal,deadline})`：参数来自可信宿主的当前设置与录音/出机许可。
  默认未启用时不调用端口。问候固定为“你好，PersonalAgent 已启动。”，不宣称任务或设备成功。
  问候释放后才启动监听；缺输出端口标 unavailable。输出失败且释放确认可继续监听，释放不明则锁住。
- `resume(同参数)`：先释放旧会话，再消费宿主重新读取的当前设置与有限许可；不重播问候。
  恢复等待期间用户再次停止会阻止重新采集。原过期参数不能恢复；不自动延期或无限重试。
- `stop/dispose/snapshot`：停止录音/播放并保留未知释放状态；不调用 `task.cancel`。
  只在原 host 返回 listening 就绪时报告 listening；请求受理不冒充设备就绪。
  快照没有文本、音频或凭据，`verification` 固定 unverified。

持续续接由原 Live host 承担；宿主适配器声明 renewsOwnLease 后，就绪时清除第二层启动计时器，
不添加独立的持续监听时限。初始就绪/问候沿原 Live 的 SESSION_MS 有限期限。其他不管理租约的
注入端口仍按所给 deadline 停止。本控制器不持久化设置、许可或音频，不注册 OS 启动项。
启动 `deadline` 必须有限、未来且不超过 JS 单个定时器可表示范围；录音/云许可仍由受信宿主检查。
调用方必须把禁用、退出、原许可撤销与系统休眠挂到 stop/signal；恢复时重新读取设置。

## Desktop 实际接线

生产组合：apps/desktop/electron/main.js 与 voice-startup-host.js；受信设置使用既有
live-voice-config.js 和 live.configure 本机 IPC，不新增 Runtime wire 或工具授权。

1. initializeLiveVoice 注入原 Live host 与 Windows System.Speech 输出端口，固定中文短句；
   只有用户勾选 startupGreeting 才实际请求输出。未安装/构建中文宿主时如实失败，不回退云模型。
2. panel 的首次 did-finish-load，以及首次运行缺配置后完成 Runtime 初始化的路径读取设置；
   continuousListening 才请求持续监听。prepare 固定可见面板，保留原麦克风/音频出机许可检查。
3. powerMonitor suspend 释放、resume 重读当前设置后恢复；stopPanelVoice、显式 Live 关闭、
   原 capture.revoke 和退出释放本包资源。显式停止/隐藏禁用本进程恢复意图，不擦除持久设置；
   中断播报或 task.cancel 继续沿原语义，不因此改变这些设置。
4. 既有语音设置 UI 增加 startupGreeting/continuousListening 两个严格 boolean；旧配置默认
   false，加密凭据保留。启用后保存立即生效，取消两项后保存释放本包会话。主对话既有语音按钮
   经 live.toggle 可关闭当前通话；不是新增供模型自行授权的业务工具。后台/主对话展示启动状态
   与问候失败。业务仍由原 Runtime/AgentArts 消费，未新增 OS 自动登录启动注册。
