# ADR-0042：按任务与沙箱合并核心审批

- 日期：2026-10-22。
- 状态：实施中；真实业务与设备验收分别记录。
- 依据：用户要求整个审批流程精简、移除反复确认提示词、人工审批只发生在卡片，修改日程等常规任务通常不超过 1～3 次核心确认；用户选定完全访问时保留下述自动同意策略。

## 决定

沿用原 `AuthorizationQuestions`、Desktop 可信宿主、TaskRuntime、Policy 与 ToolGateway。工具执行、连接器访问与结果出机先准备到同一张卡，Renderer 仅提交原 question/revision 和同意或拒绝。模型和 Live 语音不再额外要求用户说“确认”，旧独立 Runtime 卡也使用同一双按钮交互。

用户主动开启 Live 就是本次音频用途决定，不因文件沙箱模式追加麦克风授权卡。既有配置中的音频用途同意、可信可见面板、期限与停止撤销、系统设备权限继续有效；该决定不批准 Live 随后提出的日历等业务写入。

用户选择“完全访问”后，该持久策略提供应用层的自动同意，不再显示工具、连接器和必要结果出机审批卡。每个操作仍生成独立的精确单次回执并通过原 Runtime/Policy，保留后台记录；参数、配置、期限、取消及实际执行后端校验不变。切回受限模式后恢复卡片，不把历史自动决定复活成执行权限。

内部决定增加 `allow_task`：可信宿主提供稳定资源规则时，同意可覆盖同一任务内相同范围。读取和普通选定本地工作区编辑可复用；日程修改、发送、删除及未知工具默认继续绑定原参数，目标或变更内容不同则重新决定。每个新 run 仍获得独立、精确参数绑定、一次性消费的原授权回执和 Policy grant。

原 F15 工作流可由可信工作区宿主提供 `taskConsent` 分组。它绑定互反证明的原 owner、原请求/范围、配置 generation、模型目的地、原期限和固定能力/投影集合，不接受模型或 Renderer 提供的组。分为读取分析、隔离编辑与固定检查、CAS 交付。含外部检查的组在第一次卡片之前通过原生后端验证，将执行边界并入该卡，后续原节点仍逐次校验。

复用保留在当前宿主进程，不由持久记录复活；取消、原期限、资源配置变化、沙箱版本或原生执行边界变化均阻止复用。已有持久永久规则兼容保留，普通卡不再默认提供永久选项。没有通用“第三次以后自动同意”的计数器：超出原任务或资源的操作不通过数量门槛获得权限。

## 兼容与验证

Core wire 审批协议不变；`allow_task` 与 `taskConsent` 是原可信宿主内部接口的增量。旧数据不迁移、不清库，旧单次/永久决定仍可读取。UI 从可信快照的 `canReuseTask` / `suggestedDecision` 选择同意值，旧快照回退到单次。

验证覆盖同任务复用、不同目标/资源/任务、取消/重启/期限/沙箱变化、每 run 精确一次消费，以及真实 Runtime/Policy 加显式 Fake 日历的完整查找、分页、更新、读回流程。Fake 业务通过不代表真实日历或其他设备已验收。
