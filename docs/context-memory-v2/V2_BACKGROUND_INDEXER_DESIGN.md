# 全历史后台索引设计

状态为待审设计，实施范围为 V2-06。源数据仍由 Desktop 会话存储和 TaskRuntime 历史管理。沿用本地 SQLite、原始来源复核和现有权限模型。V2-04/05 的按需检索继续作为已验证基线。

## 启用和权限

- 默认关闭。只允许受信 Desktop 设置窗口由用户显式启用，说明包含当前和归档会话，本地衍生存储、磁盘/CPU 使用和清除行为。暂停保留已生成索引，恢复从检查点继续。关闭立即停止后台读取与索引查询。用户可明确清除衍生索引，保留原始会话。
- 每个本地用户/配置命名空间单独维护状态。只索引已有权限可见的消息正文与定位元数据。跳过 withheld、清除或权限失效内容。Archive 属于可见性元数据变更，已授权的本机用户可检索。工具凭据、审批秘密以及未提交的中间响应不进入索引。
- 索引检索继续限于受信设置入口、本地 `primary` 用途。无模型网络调用。摘要或向量功能若另行启用，只能使用独立已授权的本地 provider。私人会话没有自动云端注入路径。用户选择某段历史后主动提交到现有对话时，仍由原工作流处理授权与出站检查。

## 原始记录、源版本与检查点

1. 在受信 Desktop 主进程和 Runtime 公共只读入口为索引暴露限定分页。Desktop 枚举会话 ID、可见性、流式的稳定消息游标和持久变更标记。Runtime 提供对应已提交的任务消息和 receipt 版本，按既有 task/message 映射去重。索引内身份包含命名空间、来源类型、会话 ID、原始记录 ID、版本和分块方案版本。保留原件 digest 供最终核对。
2. 目前 dirty 通知是进程内提示，缺乏覆盖编辑、删除、归档和 Runtime 终态的跨重启持久游标。先确认两种原件各自可供消费的持久 revision/序号。缺失时在相应源的权威写入事务保存变更序号，或通过每会话分页核对稳定指纹并记录完成状态。后一方式需要标为分批校对，不能宣称全量变更可以用单一增量游标恢复。使用来源自己能证明的 revision 和 tombstone，避免 B4 的合法恢复与旧任务重放混淆。
3. 首次扫描为两个源各自捕获可重读的高水位和当前/归档范围，用稳定 `(source, conversationId, messageId)` 游标分页。记录扫描阶段、版本、水位和下一游标。各源基线完成后从各自水位追增量，包含扫描期间导入、编辑、删除。游标失效或发现间隙时，将受影响范围标记需校对并分批核对，避免按查询全量阻塞。
4. 复用独立衍生数据库，新增迁移管理后台工作状态、命名空间范围、来源 revision 和 episode/chunk generation。摘要按任务快照的有效期与 episode 的稳定消息版本各自管理。分段按稳定 ID、revision、内容 digest 与分块版本幂等写入。相同版本可安全重放。事务以完整消息为原子单位，同时发布全部分块和检查点。迟到或过期 lease 的批次在提交时丢弃。

## 调度、并发与恢复

索引器跟随 Desktop/runtime 生命周期，普通任务继续由现有 TaskRuntime 管理。状态为 `disabled`、`scanning`、`catching_up`、`idle`、`paused`、`retry_wait` 或 `error`。启动后只在启用且 SQLite/safeStorage 可用时开启数据读取。按低优先级分批调度，初始建议上限为每批 100 条或明文合计 1 MiB，按实测调优。长记录逐块准备并在单条记录完整后一次发布。单批解析与加密在短事务外进行，提交时检查当前 revision 和 lease。主进程让出渲染和正常查询所需时隙。

SQLite 采用 WAL、短写事务、有限 busy timeout 和带上限的退避，索引写入按命名空间串行。数据库内 CAS 和递增 fencing token 保护其他实例进入时的提交，读取使用稳定快照。暂停或关停取消在途读/准备工序，未提交批次下次可重放。崩溃后从最后一个已提交的检查点与可接管 lease 恢复，启动时核对原件版本和游标兼容性。恢复时避免重建摘要库、删除原件或长时间占用 SQLite writer。

进度仅暴露模式、当前/归档已扫描数、总数或未知、积压、最后已提交时间、最近安全错误类别及恢复操作。进度不展示正文、索引关键词或凭据。锁竞争可恢复，持续错误或损坏暂停并保留诊断。重新构建从新索引代开始，切换前各代仍按当前授权和原件版本过滤。

## 编辑、删除与二次核对

- 编辑后只允许新 revision 衍生内容可见。删除、撤回、关闭或失去访问后，读路径马上依据权威可见性/版本拒绝旧记录。变更后失效索引并撤销在途批次，后台物理清理处理已失效的密文片段与驻留 postings。旧队列重试必须无法重建已注销来源。
- 查询按访问范围预筛，候选定位回原始会话。交付前重新验证当前用户、会话可见、消息/任务完整性、未 withheld 状态、版本和 digest。原件无法读取或来源变化时丢弃并有界补充候选。返回片段从本轮核验过的原件生成，索引只提供候选与位置。
- 衍生正文和中间内容使用既有 Windows 密钥保护机制。词法 postings 初期留内存，由本机密文片段分批重建，避免把关键词写进 SQLite 明文表、WAL、日志或诊断。后续若需要持久倒排索引，先证明加密和删除语义，再另行审查。清除与 SQLite 残页/WAL 的处理应有可复验结果，产品不承诺操作系统备份的物理擦除。

## 实施顺序与验收

| 步骤 | 交付与检查 |
| --- | --- |
| 源分页与持久版本 | 验证真实 Desktop 和 Runtime 原件读回、归档、导入、清除、恢复同内容的新 revision，覆盖两个源水位并发前进 |
| 迁移、批处理、检查点 | 使用临时真 SQLite 文件、两连接和故障注入，验证空库/旧库迁移、busy、提交前后崩溃重启、暂停恢复、lease 接管及零重复片段 |
| 生产生命周期和 UI | 默认关闭时零扫描。开启后测试进度、暂停、关窗重开和撤回。Windows Electron 以合成当前/归档数据走真实加密和设置入口，无云请求 |
| 查询正确性与性能 | 竞态编辑/删除、丢 dirty 通知、同 ID 内容恢复、多片段去重、拒绝未经授权调用。逐候选读回原件，验收 [端到端指标](V2_PHASE3_EXECUTION_REPORT.md#benchmark-复核与验收门槛) |

回退先关闭索引并停止任务，切回原按需搜索，继续复核来源。保留原始记录与旧摘要，新增迁移不作倒序重写。旧版二进制若无法打开新衍生 Schema，使用受支持的备份或将后台衍生数据库保留隔离后用旧结构重建。部署验证需证明回退能正常载入既有会话且不会误用过期 index generation。
