# 开发者 harness 交付工作包

日期：2026-10-20。状态：in_progress。目标 Profile：huawei_ict_agentarts。

用户本轮优先级是先交付开发者能直接使用的完整 harness，再承接常驻智能体。最新路线为参考 Harness² 与 DeepSeek Harness 的能力、方法自主实现。上游代码、提示词和运行配置不引入本工作包。

用户进一步明确：保留本项目主对话只负责交互、澄清、汇总，产品子智能体负责实际工作的分工。原生 harness 是对子智能体执行能力的增强，不改造成任一上游产品，也不将开发工具或只读查询执行权交回主对话。#438 的主任务直答执行例外按此要求收回；#434 的单任务结果直接透传继续保留。

## 交付边界

所有产品能力须由原主对话实际消费。开发时派出的子智能体、工具注册、独立 CLI、Fake 检查或单个 PR 合并均不代表整个交付完成。实现、主对话接线、必要验证、真实模型/平台/设备验收分别记录。

用户最新执行顺序：先完成全部代码和实际调用方接线，只做解除实现阻碍所需的最必要小检查；全部源码齐全后再统一安排测试与验收。每份交付须提交 PR；Draft 保存进度，不算最终完整交付。

现有 TaskRuntime 继续负责任务、父子关系、状态、事件、检查点与执行记录；原 ModelGateway、Policy、ToolGateway、编码隔离和 Evidence 保留职责。Competition 编排继续经 AgentArts，失败保持明确错误；本轮不新增 Local 替代路径，也不建立第二任务库、调度器、授权器或模型执行循环。

## 兼容与集成

- 首轮 H1 优先使用 Runtime 内部受信配置、既有 ToolDescriptor/公开工具 Schema 与原 TaskRuntime 操作，不新增 Core wire operation 或数据库迁移。确需公共变更时先公布单一 Schema、版本、迁移影响与调用方测试。
- 默认配置沿当前兼容行为；新增多执行者由受信 composition 显式启用，模型提案不能扩大原 parent 的工具、工作区、期限或预算。
- harness 配置复用既有模型配置的加密存储和设置页，工作区复用原 codingWorkspace。执行总预算和摘要预算由用户显式配置，无新固定默认总预算；可信同步配置解析器使保存后下一任务生效，并拒绝在途计划的绑定漂移。原核实、取消和持久事实不因禁用配置而丢失。
- 候选的工具契约只有 `@personal-agent/contracts/harness-candidates` 一份：`coding.repair.trial` → `harness.candidates.compare` → `coding.repair.prepare_adoption` → 原 `coding.repair.publish`。隔离候选不直接发布，比较建议不等于采用成功；每阶段保留原 Gateway run 与持久检查点。
- 共享 main.js、主 Renderer/style 的 #434/#438/#407 收尾与后续接线串行交接。语音、harness、CI 独立模块可以并行；16GB 机器上的安装、全构建和设备服务串行安排。
- Windows 安装打包及云镜像发布不由本工作包自动恢复。应用内启动设置可以实现，实际 OS 启动项和真实付费/设备验收沿当前授权分别执行。
