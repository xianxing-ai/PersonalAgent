## 一、总体闭环：世界持续变化，任务按实际影响局部推进

外层闭环是“持续观察 → 合并当前世界状态 → 判断与目标/责任的关系 → 复用或更新局部方案 → 受控执行与验证 → 更新证据和后续决策”，代码修复只是一种执行工作包。邮件、日历、订阅、知识、设备和用户目标变化都在 F01–F28 原范围内。

事件合并复用现有连接器游标、去重身份、事实来源/版本和 Runtime 状态端口；不创建另一套事件数据库或任务调度器。事件至少保留来源版本、观察时间、实体/字段锚点、撤回/删除/修正语义和证据引用。晚到事件、源版本冲突或观察缺口不能被简单“取最新文本”吞掉；不能把模型生成的解释当作已观察事实。

世界状态同时包含用户目标和长期责任，而不只是正在运行的 PlanStep。确定性重复输入、未变版本以及仍有效的完全相同已验证经验可直接复用，避免重新询问模型。事件没有任何活跃步骤订阅时，仍需做目标/责任分诊：可能需要新任务、通知或未来计划；只有已有可验证规则确定无关，或完成该语义分诊后，才能静默处理。**不能仅凭无订阅丢弃事件。**

## 二、细锚点与步骤真实输入

源数据可按可靠结构建立细锚点，例如 Markdown 章节、JSON 键路径、代码导出符号、邮件实体/修订。锚点需要稳定定位、来源版本、内容摘要、观察时间及删除状态。解析器不能可靠定位时保持粗粒度或待核实，不伪造稳定锚点。

步骤的实际输入指纹不仅包括直接订阅的锚点，还包括：

- 任务目标、全局约束、用户要求、当前公共协议/接口契约及其版本。
- 真实消费的源片段和上游产物摘要；跨文件/跨包依赖的已确认版本。
- 构建/验证命令及参数、锁文件、编译器/运行时、配置、平台与必要环境身份。
- 生效的授权 scope、来源读取/外发限制和配置修订；只保留凭据引用或无秘密摘要，不把凭据值纳入记录。

只有输入完整性可说明、实际输入指纹未变、来源/授权仍有效且验证回执适用时，步骤才能 KEEP。全局约束或环境变化可能合法地影响多个步骤，不能为了“最小”而省略真实依赖。部分指纹未覆盖的未知依赖必须披露，不能宣称无影响。

变更先在这些真实输入上确定影响，再更新所需局部步骤及其依赖验证，避免粗粒度文档 revision 将整个图无差别变成逐节点模型重审。依赖传播可提示 RECHECK，但它不自动证明需要改代码或全量重做。

## 三、判断责任、任务类别准入与标准复用

确定性代码负责精确相等、版本、Schema、路径、授权边界、退出码、重复身份与有效期。结构检索能回答的问题优先走符号/引用/AST/目录检索；这些检查不能扩大为“确定性代码能判断所有业务影响”。

Laya 只有在**具体任务类别**经过独立验证后才承担主判断。类别验收需包含正确率、有效任务漏报/召回、歧义、升级代价和本机端到端开销；阈值由该类别 owner 根据真实评估确定，不使用模型自报 confidence 直接准入。

未验证类别默认直接交 DeepSeek 处理，可在不阻塞主任务且获准的旁路采集 Laya 样本；不能先强制调用未验证 Laya，再因未验证升级，给主链路增加固定延迟。标准、候选结构、升级条件和输出要求成熟后形成版本化判断契约复用，不为每个事件重新调用 DeepSeek“出题”。

DeepSeek 依据新观察更新局部方案、候选和必要判断标准；来源不足则请求信息，不虚构根因或验证结果。已验证 Laya 的结论、DeepSeek 的接管和确定性复用分别记录。模型/算法可以建议下一步，权限继续由原 Runtime/Policy/ToolGateway 管理。

## 四、同次决策中的局部影子及真实收益

主任务优先。同次 DeepSeek 方案/决策可附一个有实际价值的替代路径或局部 shadow 意图，避免先生成主方案，再单独为“是否需要影子”增加一个例行模型回合。当前候选契约中，这类业务数据放在 `candidate.value`，不增加顶层 shadowPlan 字段；可信宿主绑定真实 taskKey、类别及同次 decisionRef。

普通模式先交付满足要求的主结果，影子只在任务价值、可用资源、风险/失败证据或有收益依据的类别策略支持时运行。影子可以只覆盖待验证的局部步骤，复用仍有效的公共前置证据。显式比较模式等待同条件双方实际结果，再选择可交付结果。旁路判断、历史重放与隔离执行分开，不能把 route 采样写成已经执行了第二条分支。

isolated 的高级启用沿既有服务要求由 DeepSeek 配合 Laya 参与决定并留同次回执；尚未独立验证的 Laya 不成为主链路必经门槛。此处如何将“直接 teacher 主判＋非阻塞旁路参与”适配现有高级启用契约，须在下一包显式接线并记录顺序，不在本轮临时修改规则。

采样率、路由和是否继续某类影子由该类别实际可比结果调整：质量、漏报、调用/token、端到端延迟、额外构建/验证成本、人介入和资源竞争共同计算收益。未知成本、失去响应的请求及失败尝试不能从账本消失。低价值或损害主任务的影子应减少；收益不明就保持不明，不从少量成功样本推广。

经验可保存匹配前提、来源/版本、适用 scope、验证标准与有效回执，后续命中时仍验证其适用性。exact-case 缓存、流程模板、类别路由统计和模型权重训练是四种不同事实；当前经验复用不代表 Laya 权重已训练或获得泛化能力。

## 五、局部最小修复工作包

本节只记录用户待实现算法。最小修复以满足需求、保留必要行为和控制副作用为目标，不等于最少代码行数。执行前可排除已证的越界和不兼容，可用结构特征辅助选路；未运行的候选不能被宣称已经无回归或优于已验证候选。

### 1. 保存包含脏树的用户基线

记录当前用户文件、相关未提交/未跟踪内容、基线摘要、任务要求与授权 scope，保留协作者修改。独立候选工作区从该真实基线构造，不能只检出 HEAD 丢掉用户脏树；构建产物、依赖、配置及验证执行身份也需独立且可追溯，不能误用主分支旧 dist 得到假通过。

隔离空间复用现有工作树/受限工作区及工具，不新增任务库、授权器或修复专属数据库。资源调度遵循机器实际条件和主任务优先，不为本文设固定线程数或时间配额。

### 2. 确认复现的是目标错误

在未打候选补丁的真实用户基线上运行与问题定义匹配的复现检查，保留原始错误/断言/观察/Evidence：

- 环境、依赖、权限或启动故障使目标检查尚未执行：记录 INFRA_BLOCKED，交环境诊断，不用业务补丁掩盖。
- 未观察到目标错误或错误身份不匹配：记录 NOT_REPRODUCED，不宣称修好了已复现 Bug。
- 目标报错、行为或断言得到真实确认：记录 FAULT_REPRODUCED，建立原始失败回执。

以上为设计标签，尚未宣布为公共 Schema。间歇性问题按实际可复现事件序列/观测条件形成判据，不伪造“每次必败”。原本全绿的无关测试只能提供回归信息，不能独立证明目标故障已修。

### 3. 结构定位、按需上下文与版本/权限绑定

先用错误栈、目录、符号签名、结构引用与相关原文定位，提供完整语法闭合域和必要接口，再随缺失符号、真实失败或配置依赖按证据扩展。既不默认全文灌入模型，也不固定上下文行数。

候选写入范围绑定源版本和授权 scope；范围扩展需说明真实依赖并由既有宿主重新核对，模型解释不能授予越界权限。补丁匹配、Schema、路径、必要结构不变量和单文件语法由代码检查。目标是 SVG 动画触发时，几何/图层/目标与时序等必须保持的行为可形成明确不变量，而不是靠模型口头承诺。

结构变更特征用于风险提示和检查选择，不等于精确预测回归概率。不得通过删断言、放宽权限/类型、替换测试或重画无关产物获得“通过”。

### 4. 当前验证指纹与历史证据

每项检查绑定独立的 `CheckID、InputSliceFingerprint、命令/参数、执行环境、Stage、Outcome、FailureSig、Evidence`。这些是下一轮记录语义，不是新建持久化系统的授权。实际记录优先挂接原 Runtime checkpoint/Artifact/Evidence，以目标图的 plan 引用关联；保留 goals 的 fact/goal/decision/plan 现有边界，不把修复细节硬塞入其 Schema。

历史回执即使当时通过，若当前源版本、输入、环境、检查定义或授权变化，仍只是 **HistoryEvidence / STALE**；不得直接提升为当前 PASS。复用必须核对完整指纹、有效性和当前源读回。当前任务真正通过，要求目标复现检查从失败变为通过，且约定的必要行为/回归检查仍满足要求。

### 5. 按真实反馈推进，识别无新证据与振荡

进展用多项检查的状态向量判断，不以“失败数必须严格减少”或单个全局阶段标量代替。模块开始成功加载后出现更多真实断言失败，可能是有效推进；配置、依赖或检查输入变化后重跑也可能合理。每次应说明哪些检查仍适用、哪些已过期、哪些反馈是新增证据。

去重/防振荡使用确定性机器特征：输入切片、源/补丁/适用的结构摘要、失败测试身份、错误类型/位置、相关配置与检查状态。自然语言根因假设可用于解释，不能换措辞就绕过重复判断。归一化 AST 只在语言解析可靠且保留语义相关指令/内容时使用，不能简单删空白/注释当通用语义哈希。

输入与验证条件未变、检查无实质推进且回到已尝试状态或 A↔B 循环时，停止该无效路径，保留原始反馈并交 DeepSeek/用户进一步判断。新证据应能解释下一尝试为什么可能不同。本文不固定三轮、60 秒或失败次数；继续执行仍受原任务 deadline、预算、取消及用户授权约束。

默认不做 ddmin/多轮撤块测试。现有测试不完备时，“删掉防御代码仍通过”不证明可安全删除。发现顺带改动时先用范围/结构证据要求候选收敛；是否做额外删减验证由具体必要性决定，不开展盲目撤改风暴。

### 6. 选择已验证候选并 CAS 交付

比较只限已经探索且满足约定验证的候选，不声称找到全局最优。改动范围、副作用风险、保持的行为、质量和实际成本共同构成 owner 明确的选择标准；未知项保留未知。

交付前重新读当前用户源及有效验证指纹，经原补丁工具执行 CAS。发生冲突时保留用户当前内容与候选两方，不覆盖、不清理他人变更，也不盲目用新幂等键重写。未知写入先通过原 Runtime operation/result 核实，不从暂停中的算法推导重试权限。任务终态、Artifact 和 Evidence 始终由可信执行链记录。

## 六、对照实验与验收

在相同事件流、原始资料、权限、工具、模型配置和输出验收要求下比较三组，保留合理缓存与工具复用，不能给基线故意全量重做增加无意义成本：

| 组别 | 保留的能力 | 要识别的增量 |
| --- | --- | --- |
| A | 合理的 DeepSeek 工作流＋现有缓存/工具/验证 | 可用工程基线，而非“每步无脑重调模型”的稻草人 |
| B | 与 A 同基础，增加确定性事件合并、细输入增量和有效证据复用 | 无 Laya 主判断时，增量处理本身带来的收益与成本 |
| C | 与 B 同基础，增加经类别验证的 Laya 路由及有收益依据的自适应局部影子 | Laya 与影子各自额外成本、净收益及质量影响 |

分别记录冷启动与稳态；事件集覆盖无关/重复变化、全局约束变化、局部真实影响、未订阅但与责任相关的新事件、经验失效、间歇故障和必要的高风险比较。不能预先按收益目标只选择容易被过滤的样本。

指标至少包含：正确完成任务数、有效任务漏报/歧义、最终质量/新增回归、已完成步骤返工、各阶段模型调用和 token、缓存与重复输入、失败/丢响应请求、端到端延迟、CPU/GPU/内存/构建资源、工具/验证次数、重试、人介入时间，以及实际可核实的费用。计价/账单未知时注明未知，不从 token 直接臆算真实收费。

按正确验收任务核算成本和资源净收益，分母为零时不计算收益比。共同报告“减少调用但漏掉有效任务”之类退化，不用单项调用下降宣称总体更优。采样/路由阈值由实际类别评估确定；附件的 35%、20%、80% 或理论倍数不构成保证。
