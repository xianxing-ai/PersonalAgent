# F16/F17 Linux 提供者接线与验收（2026-10-31）

范围：PR #531 的 `huawei_ict_agentarts` F16_N01 与 F17_N03→N04 受信来源提供者。独立分支 `codex/pr531-f16-f17-cloud`，已合入主对话公布的 `43d0d37012264a00aa4e48ef370f6f25cbc290c2`，包含原 configured worker；不另外实现 worker、bridge 或授权层。

本包不表示 F16/F17 整图已接通或 #531 可合并。共同入口、真正的逐节点 completion verifier、固定 AgentArts deployment 和整图真实验收仍由主对话整合。本包不修改云环境配置、不发布云环境、不更新 #531 原分支、不合并 PR。

## 生产行为

- F16 校验三条原 `github.actions.run.list/job.list/log.read` 的 Runtime 执行记录、原 child/parent/command、参数摘要、scopeRef、工具版本、confirmed 结果和 Evidence。仅接受同一 repo、失败且 completed 的 run/job、明确 job.runId 与所选 HEAD。外来任务、替换参数和 unknown 回执不可使用。
- `createF16CiFailurePorts` 冻结每个 parent/session 的选择与来源快照。每次 HEAD 核验请求都具有独立 commandId，经注入的原受信 child 工具通道调用 `workspace.git.head`；端口只返回原持久回执引用，不接受直接传入 HEAD 字符串作为该生产提供者的证明。
- F16 执行后保存 `f16:ci-failure:<operationId>` 来源快照。出机许可 await 后重新读取原来源和新 HEAD；完成回执导出时还校验原 child 的 confirmed 输出和持久来源快照，禁止用相同文本替换另一条来源。
- F17 在 N03 分派前持久绑定配方摘要和已有 HEAD/文件指纹读回；N03 后校验原命令的真实非零退出码、stdout/stderr、前后 HEAD/文件指纹一致、读回顺序以及原 Policy/Gateway 记录。配方来自与 `createWorkspaceCommandTool` 相同的受信配置，不保存环境变量值。
- F17 使用现有 `locateTestFailures`，关闭源码片段读取。原失败输出仍保存在原 tool-result checkpoint，新的本地报告保存原来源、输出摘要、命令版本/配方摘要、HEAD、指纹及解析出的调用栈。没有第二套执行器或任务库。
- `f17:failure-report:<operationId>` 只写入原报告 child。对外投影只有计数、内容寻址 reportRef 和 `all6PassResolved:false`，不会把失败定位说成测试已修复。导出前后重新检查命令与版本来源。unknown 保留原 child，读回不重跑复现命令。

## 供主对话接线的精确接口

新模块尚未从共享 `application.ts` 增加 re-export；该文件按分工由主对话统一修改。请通过公开 application 出口导出下列工厂后再供 Desktop 使用，不从 Desktop 深层导入 Runtime 私有文件。

```ts
// application/f16-ci-failure-ports.ts
createF16CiFailurePorts({
  application,                 // Pick<RuntimeApplication, 'runtime' | 'readHostToolTask'>
  selectionCheckpointKey,      // 受信命名空间前缀；内部再追加 :<sessionId>
  now,                        // () => Date
  invokeWorkspaceHead,         // (scope, F16HeadRequest) => Promise<F16SourceRead>
})
// 返回 bindSelection(scope, binding)、resolveFailure(scope)、readCurrentHead(scope)、
// assertSelectionCurrent(scope)。后三者接入已有 createRuntimeF16CiFailureHost。

// application/f17-reproduction-ports.ts
createF17ReproductionPorts({application, checkpointPrefix, recipes, now, invokeWorkspaceHead})
// 返回：
// prepareReproduction(scope, {operationId, repository, recipeId, beforeHead}) — N03 分派前
// bindReproduction(scope, {operationId, repository, command, beforeHead, afterHead}) — N03 读回后
// resolveReproduction(scope, {taskId, operationId, arguments}) — 注入 F17 host

// application/f17-configured-driver.ts
createF17ConfiguredDriverResolver(application, {name: configuredToolName, version})
// 返回 (scope) => 原 configured worker 的 :graph checkpoint key。
// 注入 createRuntimeF17FailureReportHost.driverCheckpointKey；旧固定字符串仍支持。
```

`F16SourceRead` 精确形状：

```ts
{ taskId, runId, toolVersion, scopeRef, arguments }
// taskId 是原 source child；runId = scopeRef = 'host-tool-' + taskId。
// arguments 必须和该 child 原 host-tool-intent 及参数摘要完全一致。
```

`F16HeadRequest` 精确形状：

```ts
{ commandId, toolName: 'workspace.git.head', toolVersion: '1.0.0',
  arguments: {repository}, deadline }
```

`invokeWorkspaceHead(scope, request)` 必须复用原 Runtime/Policy/ToolGateway child 通道，按 request 的 commandId、参数、版本与 deadline 原样提交；为 child 保留现有 `coding-repair:parent` 以及 parent 的 `coding-repair:host:<commandId>`。返回 confirmed 原引用；pending、拒绝、unknown 不得伪造成字符串结果。前后 HEAD/复现命令及 GitHub 三条读取使用同样的原 child 绑定。权限由现有 Policy 授予，提供者自身不签发授权。

F17 `recipes` 必须与实际命令工具使用的不可变配方表相同。`beforeHead` 在 prepare 前完成，原命令在 prepare 后分派，`afterHead` 在原命令完成后取得；HEAD 与限定文件指纹不一致时拒绝报告。指纹覆盖范围由已有 Git 工具的受信 allowedPaths 定义，不能据有限文件指纹宣称整个工作区具有不可变隔离。

两个 host 还需原同步 `assertCurrent(scope, context)`、`requiredScopes`、`now`、精确目的地 `authorizeExport`。F16 的同步 gate 同时调用 `ports.assertSelectionCurrent(scope)`；F17 的 workspaceRoot 是对应原命令的受信目录。configured worker 的 receipt-stage `authorizeExport` 必须调用对应 host.authorizeReceipt，并传入原 localTaskId/runId/scopes/authorizationRef/deadline/signal 与原结果，不能仅检查 `true` 常量。

configured-worker 采用既有 `RuntimeConfiguredWorkflowOptions`。F17 resolver 只定位原 pending proposal 绑定的 checkpoint，校验提案摘要、revision、deadline 和 session；它不启动 graph。不要复制 configured worker 实现。F16_N04 真实测试意图审核、F16_N05 真实重跑结果、F17 其他节点和逐节点 completion verifier 仍需真实提供者；本包没有提供放行它们的默认值。
