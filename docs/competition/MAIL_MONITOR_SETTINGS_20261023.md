# 邮件监测一键启动与通知设置精简

目标为 `huawei_ict_agentarts`，工作树 `D:/worktree/f809/PersonalAgent`。用户反馈 QQ 已收到邮件，但 Desktop 无分类或提醒，且订阅间隔、截止时间、通知范围等参数需要手填。

本次沿用原 Connector Watch、Runtime Scheduler、Policy/ToolGateway、邮箱分类和通知宿主：设置页提供启动/停止监测入口，可信宿主填入默认轮询与期限，自动启动本地分类模型并展示真实状态。正常会话的来源许可和原审批仍生效；不创建第二套定时器，不从 Renderer 调用连接器。通知设置以可选范围和默认值代替空白技术参数，低频选项收进高级设置。

兼容性：原显式订阅参数继续有效；对话省略间隔/期限时由可信宿主生成默认值，原审批输入与实际生效参数分别绑定，不修改已批准输入。配置页操作通过原宿主任务入口执行，重复点击复用在途任务及已有有效订阅。关闭应用仍释放本机读取许可，重启后须从清楚标注的启动入口恢复。

默认行为：每 2 分钟检查一次、本次监测 8 小时。首次没有通知策略时通过原通知配置宿主应用系统横幅默认值；已有静默、频率及安静时段策略保持有效。设置页正常只需选择通知范围、提醒方式和通道；频率、摘要及安静时段放入高级设置，时区可自动识别。

本轮确认的缺陷：原监测宿主没有处理邮件读取的 `failed` 状态，读取任务失败后仍会停留在“读取中”；现已明确停止并展示失败，可重新启动。卡片把缺少未读数当成“尚未拉取邮件”，现分别显示已分类数量、未读数和监测状态。云复核失败单独展示，不据此判定本地读取失败；原未知结果任务不自动重复发送。

验证（Node 24.15.0）：

- Connector Watch 24 项通过，覆盖默认参数、原批准输入及有效期限防替换、设置页单次启动/停止、过期与重启、读取失败退出、授权窗口失效时在工具执行前取消。
- 邮件设置、连接卡片、云复核宿主及通知页合计 27 项通过，无跳过。通知页通过 `PA_NOTIFICATION_UI_TEST=1` 运行真实 Edge 渲染和交互；邮件按钮调用、无技术参数输入、旧范围草稿保留均通过。模型、IPC 回执和邮箱数据为显式夹具，不是实机收信证据。
- 架构门禁 3 项通过；Desktop 主入口语法和 CRLF 感知差异检查通过（该邮件控件在原提交中也是 CRLF）。
- 页面截图保留在本机 `.cache/mail-monitor-ui/`，未提交私人数据或配置。

真实验收边界：当前本机可用内存曾读到约 0.65 GiB，未达到 Laya 现有 2 GiB 启动要求。用户明确选择保留抖音、先完成代码修复，因此本轮没有重启正式应用、启动 Laya、发送新测试邮件或发起云端测试；真实分类与系统横幅验收仍未完成。没有把 `EXTERNAL_FAILURE` 直接归因为云平台故障，也未将历史成功记录当作本轮成功。

本工作包为 Desktop JavaScript 和装配修改，沿用已有构建产物，未切换主线或修改 TypeScript 公共契约。验证选用受影响宿主和真实浏览器页面；未运行涉及无关 Local Profile 的整套 Runtime Application 桌面冒烟或全仓 `npm run check`，后续正式应用验收仍需覆盖新的 IPC 启动入口。
